- **Lanes: each slot belongs to a lane, one agent per lane.** Parallel agents that re-record the same generated files or pins void each other's checks, so a lane owns a set of files and only its agent changes them. {{LANES}} The lanes and their caps are `lanes` in `.claude/foreman.json` (a `lanes` list in `tmp/ops/backlog.json` overrides them); every backlog item has a `lane`, and an item or agent with an unknown lane counts under `flex` (else the last lane).
  - The one slot goes to the best ready item across the lanes: what {{OWNER}} is waiting for first, then {{OWNER}}'s `priority`, then `rank`; `flex` only when the other lanes have nothing ready. A lane with room (fewer agents than its cap) may start its own best ready item.
  - A feature that spans lanes becomes linked items (`B-12a` in one lane, then `B-12b` in the next with `dependsOn`): the first merges the contract, the second builds on it while the first lane moves on. A small part in another lane may stay in its item when it touches no file that lane owns.
  - Keep **at least two ready briefs in each lane** (`minReady`; the lane `flex` keeps none) so a freed slot never waits for a brief, and refine them ahead: written against the merged state, the item's questions for {{OWNER}} already asked. The heartbeat checks it: `briefs low: <lane>` or `pipeline empty: <lane>` in a check-in, `LOW` on `lead_status.py`'s lanes line. The missing briefs come first in that turn, before anything but a merge. `pipeline empty` means nothing defined is left to brief in that lane: tell {{OWNER}} at once, with what you propose to define next.
  - An agent changes only the files its lane owns; a file another lane owns, or one that shows up in many outputs, needs the lead's OK first.
