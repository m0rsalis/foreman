## Working with parallel agents (Foreman)

A **lead** session plans, delegates to background agents, merges and talks to {{OWNER}}. Agents build. These rules are {{OWNER}}'s; follow them without being told again. The kit's skills carry the step-by-step routines: `/foreman:restore`, `/foreman:checkpoint`, `/foreman:check-in`, `/foreman:brief`, `/foreman:start-agent`, `/foreman:revive`, `/foreman:merge`. Settings: `.claude/foreman.json` (owner, agent cap, lanes, locks, full check and its cache, panel); `/ops` opens the Ops panel.

- **The lead's session name is `{{LEAD}}`.** Agents report to it by that name, and the lead addresses agents by theirs. If the lead runs under another name, update `lead` in `.claude/foreman.json` and the heartbeat.
- **Agents run as background sessions**, so a clear of the lead never touches them. Start one from the main checkout: `{{CLAUDE}} --bg -w <task> --agent {{SLUG}}-engineer|{{SLUG}}-implementer|{{SLUG}}-checker --permission-mode auto --name <task> "<prompt>"` (`-w` gives it its own worktree, `.claude/worktrees/<task>`). The prompt points at the brief file and says: `tmp/` paths mean the main checkout's `tmp/`; report to `{{LEAD}}` by name with SendMessage only (one message per merge or stop, then the final report; a hand-back line before stopping on a usage limit); if the lead is unreachable (a cleared lead has no process), send the report to `{{HEARTBEAT}}`, keep it as the last text of the session and carry on; run long commands in the background; no sub-agents. The lead files each report as `tmp/ops/reports/<task>.md` (an agent's sandbox cannot write the main checkout's files). `/foreman:start-agent` has the exact command. In-process sub-agents (the Agent tool) die with the lead's clear: use them only for jobs that end before the next clear.
{{ACCOUNTS_RULE}}
- **Token budget.** Most usage is the context re-read on every call, and calls with a context over 400k tokens cost the most; the lead is a fifth of it, the agents four fifths. So:
  - **One session per stage.** A background session does one stage (one PR, or one stop for {{OWNER}}) and ends with its report; the next stage starts a fresh session from the brief plus that report, not `--resume`. `--resume` only finishes the same stage after a usage limit or a stall.
  - **Quiet output.** Long commands go through `{{TOOLS}}/quiet.sh <name> <cmd>` (the full log in a file, a short summary printed; it composes with `queue.sh` and `fullcheck.sh`); read logs and big files by range (`grep`, `sed -n`, `Read` with an offset), `git diff --stat` before a full diff, never `cat` a whole log. Shell output is most of what enters an agent's context.
  - **One report per stop.** Agents message the lead at a merge or at a stop for {{OWNER}}, not with progress lines: each message costs the lead a turn at its full context.
  - **The heartbeat wakes the lead only when something changed** (`{{TOOLS}}/needs_lead.py`).
  - **Contexts compact early** ({{COMPACT}}, not the 1M default): `autoCompactWindow` and `CLAUDE_CODE_AUTO_COMPACT_WINDOW` in `.claude/settings.json`, which every session in this repo reads (lead, background agents, sub-agents). `/autocompact` shows the window in force. Raise it only for a task that must hold more at once, and say why in the brief.
- **The agent cap** is `agentLimit` in `tmp/ops/status.json` (default `agentCap` in `.claude/foreman.json`: {{CAP}}). {{OWNER}} sets it and changes it with the usage limits; more agents than the machine can carry slow every agent. Keep the rest in the backlog and start the next when a slot opens. A parked agent (session stopped, worktree kept, waiting for {{OWNER}} or a deploy) does not hold a slot; resume it with `--resume` when its wait ends and a slot is free. When {{OWNER}} makes something "priority one", pause the others (kill their checks, release their queue locks, commit work in progress, end the turn) until it is delivered, then resume them.
- **Pick the model by difficulty; the middle tier is the default:** `{{SLUG}}-engineer` (Opus) for hard logic, architecture, complex merges, design documents and anything where fidelity is the point; `{{SLUG}}-implementer` (Sonnet) for well-specified changes, UI from a clear brief, doc updates, pipelines with clear rules; `{{SLUG}}-checker` (Haiku) for rerunning a full check and merging when green, watching queues, collecting results. The definitions live in `.claude/agents/` and are this project's to edit.
{{LANES_RULE}}
- **The backlog** is `tmp/ops/backlog.json`. {{OWNER}} describes a feature; the lead and {{OWNER}} define it together; the lead writes it in (status `defined`; a brief file and status `ready` once it can start). When a slot opens the lead takes the best ready item (of the slot's lane, with lanes): {{OWNER}}'s `priority` (1 = next) beats the lead's `rank`, every `dependsOn` item is done, it is not blocked; prefer what relates to the current code and the running agents. When unsure, ask {{OWNER}} with a recommendation. {{OWNER}} can set or change a priority at any time (it applies to the next pick). The lead keeps backlog.json current at every checkpoint (status, lane, agent, pr, rank). The Ops panel and `lead_status.py` show it; the format is in `{{TOOLS}}/README.md`.
- **Briefs are self-contained** (`/foreman:brief`): {{OWNER}}'s words, files to read first, the state inherited, what to build, its lane and the files to leave alone, tests, branch names, report format. The agent definitions already carry the machine rules.
- **Shared resources go through the queue:** `{{TOOLS}}/queue.sh <lock> <command...>` (FIFO across every session and worktree, locks in the main checkout's `tmp/agent-locks`; declared locks: {{LOCKS}}). One lock at a time. `{{TOOLS}}/fullcheck.sh` runs the full check ({{CHECK}}) through the queue before every merge, in the background with output to a log; read its final `FULLCHECK:` line, which names the commit it checked (`all green at <sha>`). It skips a step that already passed on the same inputs when the step has a `cache` in the config (`suite_cache.py`; `FORCE_ALL=1` runs everything). {{MAINCHECK}}
- **Merge discipline:** merge only on a `FULLCHECK: all green at <sha>` line whose sha is the PR's head commit. Then `git fetch`, and `git merge-base --is-ancestor origin/{{MAINBRANCH}} <that sha>` before `gh pr merge <n> --merge`: if it fails, `{{MAINBRANCH}}` moved after the check, so merge it into the branch and run the check again (cached steps make that cheap). When two PRs are close, announce an order; two checks racing for the same `{{MAINBRANCH}}` starve each other. Never force-push `{{MAINBRANCH}}`.
- **Processes:** agents kill only processes they started, by pid, and every `pkill`/`kill` pattern names the agent's own worktree path; never `pkill -f` or `pgrep -f` on a pattern the waiting shell's own command line contains (it matches itself and never ends): wait on a pid (`while kill -0 <pid>`) or a file. Never stop a queued job mid-run; the queue clears dead owners by itself.
- **Stalls and handovers:** a stalled agent is resumed with a message telling it to run long commands in the background (SendMessage by name). To change an agent's model or recover a dead one, ask it to hand back (what is done, what remains, anything non-obvious), then start a fresh agent in the same worktree with that hand-back in its brief. Do not keep resuming old agents for new work (Token budget). With one report per stop a quiet agent is normal, so `needs_lead.py` finds a stuck one without messages: the check-in notifies once when an alive agent has been idle 20 minutes with no command running, or one command has run 150 minutes. Stop an agent's session as soon as it has filed its final report, so a finished agent never trips it.
{{USAGE_RULE}}
- **After a merge, remove the agent's worktree:** `{{CLAUDE}} stop <id>`, then `{{CLAUDE}} rm <id>` (it removes the worktree when that is safe). It refuses while the worktree has untracked files: check they are saved or not needed, delete them, `rm` again. Then `git worktree prune`, `git branch -d` for the merged branch (and the `worktree-<task>` branch `-w` made), `git fetch --prune`. Worktrees can hold gigabytes of caches each. Never remove `.claude/worktrees/main-check` (the safety net's, detached on `origin/{{MAINBRANCH}}`).
- **Background sessions can die silently** (blocked, no pid) or end on a usage limit (state `done`). Revive with the FULL session id and a message naming its worktree: `{{CLAUDE}} --bg --resume <sessionId> "<message>"` (`/foreman:revive`; it keeps its agent, model and permission mode). A resumed session may start in the main checkout: the message names its worktree and says to work only there. `--resume` on a session that is still running starts a copy: check `{{CLAUDE}} agents --json --all` first.
- **Keep working through usage limits:** a check-in every 30 minutes (at :17 and :47) resumes agents stopped by a usage limit, an API error or a stall, fills free slots from the backlog and does merge housekeeping. It comes from `{{HEARTBEAT}}`, a Haiku background session whose own cron runs `{{TOOLS}}/needs_lead.py` and messages the lead "check-in (heartbeat)" only when the agents, the open PRs or the backlog changed, a lane ran short of briefs, a usage window crossed its threshold, a stall was found, or after two quiet hours, because the lead's CronCreate jobs die with a clear. If `lead_status.py` shows no `{{HEARTBEAT}}`, start it with the command in `{{TOOLS}}/heartbeat.md`. Its cron expires after 7 days: restart it weekly.
- **Keep `tmp/ops/status.json` current** (agents, sign-off items) whenever an agent starts, hands back or merges: the Ops panel shows it to {{OWNER}}.
- **Previews for {{OWNER}}** (images, recordings, reports to look at) go in the main checkout's `tmp/` (the panel lists the configured preview folders), never only in an agent's worktree.
- **Code comments:** agents start every session without memory and read the files they change, not the design notes, so a comment beside the code is where a rule reaches the agent that could break it. Say why, the limits or invariants, the units, and the decision or doc section the code implements. Never restate the name or the code. No history (who asked, when, what it used to be): that lives in git and the docs. Update or delete a comment in the same change as its code; a stale comment misleads an agent more than a missing one.
- **Ask {{OWNER}} one theme at a time,** with a recommendation. Record decisions in the docs in small PRs.

### Lead checkpoints

The lead's conversation is not the record; files are. **The lead never clears itself**: a cleared desktop session has no process until {{OWNER}} writes, so agents and the heartbeat cannot reach it. Long conversations are summarised automatically, and {{OWNER}} clears by hand when they want a fresh start. A clear ends the lead's in-process sub-agents, background shell tasks and CronCreate jobs, while background sessions carry on; {{OWNER}}'s next message starts the restore.

- **The record** (all of `tmp/` is gitignored and machine-local): `tmp/ops/status.json` (running agents with kind, model, worktree, branch, step, session id; sign-off items for {{OWNER}}; the cap and today's priority line), `tmp/ops/backlog.json`, `tmp/ops/lead-notes.md` (where things are, {{OWNER}}'s directions not yet built, open questions, non-obvious know-how; overwritten at each checkpoint, about a page), `tmp/ops/briefs/<task>.md` (a self-contained brief for every ready item, written before it is marked ready), `tmp/ops/reports/<task>.md`.
- **Checkpoint** (`/foreman:checkpoint`) whenever an agent starts, hands back or merges, and before every clear: update status.json and backlog.json, rewrite the lead notes, write briefs for anything ready, record {{OWNER}}'s new decisions in the docs.
- **Restore** (`/foreman:restore`) at the start of a lead session or after a clear: read the lead notes, run `python3 {{TOOLS}}/lead_status.py` (agents against live sessions, backlog, lanes, locks, worktrees, sign-off, open PRs), act on reports not yet read, revive dead agents, start ready items from their briefs, carry on.
